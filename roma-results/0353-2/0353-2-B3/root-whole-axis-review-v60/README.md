# 整根候选与人工定义 V60

本轮按用户最新要求：只显示核对明确的可见轴线编号，其余不强行标号，允许点选候选整根后人工定义。
正式初始编号只有0030和0059，由四期原始RGB中的可见轴线核对；不是根系生物学真值或独立准确率声明。
0059把截图中0104、1241等被割裂的近水平轴线统一；四期可见原有根段同号。不可见长度未补画。
本轮未训练模型，所有四期像素层、原有根线坐标与单像素owner图均与V59输入完全相同。原始上传14和所有旧版保留。

## 操作
1. 下载annotate.html用Chrome/Edge打开。已内置本轮数据，不需要导入旧JSON。原图使用已有固定地址；首次加载需联网，也可选择匹配本地PNG。
2. 点击原图可见根线，整条候选高亮，下方显示四期相同范围的真实RGB与实际根线。没有匹配的期次明确显示未匹配，不复制前期像素，也不因此判新生。
3. 交叉处可能有多个走向，用“走向候选”切换；“接入另一段”将另一完整候选加入，四期已有对应同步；“移出选错整段”把原候选整条路径移回未定义。若原候选已在交叉处接错，可展开“两点分开”，选两端预览再确认；新分出的路径仍是未定义候选，不自动生根号。随时撤销。
4. 核对走向与四期后，选择已有根、独立新根、已有侧根或新生侧根，输入根号或母根号，再点确认定义。定义是用户行为，不是自动确认。
5. T1已有独立根只分配0001--0312；没有T1对应的候选不能自动追加裸编号。确认独立新生用N-xxxx，新侧根为母根-Nx。后期持续、延长均保留同一身份与编号。
6. 输入已经定义的根号，会明确归入那条根的四期体系；已有侧根和新生侧根分别编号，与母根家族同色。定义根号不修改原有根像素或时序像素类别。
7. 保存进度JSON或可编辑HTML，之后恢复。V60进度保留用户定义、未定义状态和四期路径。旧版自动稿导入时仅作为未定义候选，不会被当成全部已确认标注。

## 不确定性与数据
未定义候选内部使用U-技术句柄，便于保存和点击，它不是生物根号，不显示在原图及四期预览。大量短交叉残片仍存在于原图结构中，不当成新增根计数。
候选的完整走向及跨期对应仍可能有误，需人工检查、接入或移出；不能保证一个候选就一定是一条真实生物根。遮挡处保留待核，不直接认定新生。
review_project.json是可导入编辑稿；review_data_verification.json核对像素和根线不变；browser_verification.json只验证实际编辑、定义、保存与恢复，不代表根系识别精度。
source_v59.json本地逐字节留存上一版输入。root_structure_draft.json和重建日志仅为未发布算法实验，不是交付人工标注；不要混用。

## 代码
source/reconstruct.py构建方向连续及跨期对应候选；ROOT_PREVIEW60=1用于无正式编号的走向提议。
source/prepare_review.py把候选转为未定义编辑对象，只保留上述两条可见轴线号；source/build_review.py构建网页，source/review.js实现人工定义。
source/verify_review.mjs为真实浏览器鼠标、键盘、文件恢复及HTML重开检查。工程根/workspace/LI。
